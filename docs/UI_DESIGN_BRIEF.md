# 文巡智护 UI 设计需求

最后更新：2026-09-24

## 1. 项目是什么

文巡智护是面向文物建筑的智能巡查与保护整改 Web 系统。巡查人员录入现场记录和照片，智能体生成检查计划、风险草案和规范依据；复核人员确认风险并创建整改任务；整改责任人提交证据；复核人员审核后关闭任务并归档。

产品是专业工作台，不是营销网站、数字人讲解或聊天机器人。智能体只提供建议，最终确认、审批和归档必须由人完成。

## 2. 用户与核心流程

| 用户       | 主要任务                                   |
| ---------- | ------------------------------------------ |
| 巡查人员   | 创建巡查、录入现场记录和照片、运行智能分析 |
| 整改责任人 | 查看任务、提交整改说明和证据               |
| 复核人员   | 确认风险、创建任务、通过或驳回整改         |
| 管理员     | 管理建筑、用户、规范知识库和报告           |

```text
创建巡查
-> 智能体生成检查计划、风险草案和规范依据
-> 复核人员人工确认风险
-> 创建整改任务并指定责任人和期限
-> 责任人提交整改证据
-> 复核人员通过或驳回
-> 全部风险关闭后生成巡查报告
```

## 3. 页面结构与主操作

| 页面                   | 页面结构                                                            | 页面主操作                       |
| ---------------------- | ------------------------------------------------------------------- | -------------------------------- |
| 登录页                 | 左侧产品说明，右侧登录卡                                            | 登录                             |
| 工作台                 | 左侧导航，顶部指标，中央最近巡查，右侧本月闭环                      | 新建巡查                         |
| 建筑档案列表           | 筛选条，建筑卡片或列表                                              | 查看建筑、新建巡查               |
| 建筑档案详情           | 建筑概要，历史风险，巡查记录                                        | 创建巡查                         |
| 新建巡查               | 左侧表单，右侧智能体处理说明                                        | 保存并进入巡查                   |
| 巡查详情与智能体工作台 | 左侧原始记录、计划、风险、规范依据；右侧 Agent 运行记录和人工关注项 | 运行分析、确认风险、创建整改任务 |
| 整改任务列表           | 状态筛选，任务列表，期限和证据数量                                  | 打开任务                         |
| 整改任务详情           | 任务概要、验收标准、证据区、复核区、时间线                          | 提交证据、通过、驳回             |
| 规范知识库             | 文档列表和条款展开区                                                | 查看原始来源                     |
| 报告中心               | 可归档巡查列表，报告数据入口                                        | 查看报告                         |

巡查详情是最重要的页面。风险、依据、责任、期限、证据和状态必须能被同时理解。

## 4. 角色与操作权限

| 操作           | 巡查人员 | 整改责任人 | 复核人员 | 管理员 |
| -------------- | -------: | ---------: | -------: | -----: |
| 查看巡查       |       是 |         是 |       是 |     是 |
| 创建和提交巡查 |       是 |         否 |       是 |     是 |
| 运行智能分析   |       是 |         否 |       是 |     是 |
| 确认风险       |       否 |         否 |       是 |     是 |
| 创建整改任务   |       否 |         否 |       是 |     是 |
| 提交整改证据   |       否 |         是 |       否 |     是 |
| 通过或驳回整改 |       否 |         否 |       是 |     是 |
| 管理规范知识库 |       否 |         否 |       否 |     是 |

无权操作时不要显示可点击按钮。页面必须提供明确的权限不足说明。

## 5. 必须表现的状态

| 区域     | 状态                                         |
| -------- | -------------------------------------------- |
| 智能分析 | 待分析、分析中、分析成功、分析失败、降级模式 |
| 风险     | 待确认、已确认、已排除、已消除               |
| 整改任务 | 待处理、处理中、待复核、已驳回、已关闭       |
| 期限     | 正常、临近、逾期                             |
| 证据     | 未提交、已提交、证据不足、复核通过           |
| 规范依据 | 已匹配、信息不足、来源不可用                 |
| 文件     | 上传中、成功、格式错误、文件过大、上传失败   |
| 系统     | 正常、接口超时、只读降级、权限不足           |

特别要求：

- 风险未人工确认前，不能显示“整改中”。
- 没有可靠规范依据时，显示“信息不足”，不能编造条款。
- 证据不足时可以驳回，并明确显示驳回原因。
- 已关闭任务不能重复提交，但可以查看完整历史。
- 模型失败时保留原输入，并允许使用预置结果继续演示。

## 6. 演示数据和文案样例

建筑样例：

```text
编号：HB-A01
名称：示范木构院落 A-01
年代：清代
地区：华北地区某历史文化街区
标签：火灾、水患、植被、游客活动
```

巡查样例：

```text
季节：秋季
天气：暴雨后
现场观察：正殿东侧排水沟积水，墙脚出现新湿痕，周边有杂草根系侵入。
```

风险样例：

```text
标题：排水与渗漏风险
等级：高风险
置信度：86%
建议：复核排水路径、墙脚和地下空间，清理堵塞并记录复查结果。
不确定项：需要专业人员确认水痕是否来自新增渗漏。
```

规范样例：

```text
标准：WW/T 0125-2025 文物建筑防火设计规范
条款：1 范围
来源：全国标准信息公共服务平台
```

任务样例：

```text
标题：处理东侧排水与墙脚渗漏
责任人：演示整改人
期限：3 天内
验收标准：提交处理说明、风险位置照片和整改后对比证据
```

## 7. 视觉系统

| Token    | 值        | 用途               |
| -------- | --------- | ------------------ |
| 背景     | `#F4F7F5` | 页面底色           |
| 面板     | `#FFFFFF` | 内容表面           |
| 主文字   | `#1F2A26` | 标题和正文         |
| 次级文字 | `#5A6963` | 说明和辅助信息     |
| 边框     | `#D8E1DD` | 分隔和输入框       |
| 主色     | `#1F6F62` | 主操作和正常状态   |
| 待处理   | `#A96F1F` | 提醒和临近期限     |
| 高风险   | `#C2412D` | 高风险、错误和驳回 |
| 信息色   | `#2F6591` | 分析中和系统提示   |

设计规范：

- 中文字体使用 Noto Sans SC 或系统无衬线字体。
- 编号、版本号和模型名使用等宽字体。
- 正文字号 14 到 16 px，页面标题 28 到 36 px。
- 卡片圆角 6 到 8 px，按钮高度至少 44 px。
- 间距使用 4、8、12、16、24、32、48 px 的节奏。
- 图标使用 Lucide 线性图标，不使用 emoji。
- 状态不能只靠颜色，必须同时使用文字、图标或形状。

不要使用营销 Hero、大面积米黄加故宫红、紫色科技渐变、发光球体、数字人、聊天窗口或卡片套卡片。

## 8. 图片与数据边界

- 可使用团队自拍、明确授权或 CC0 的文物建筑外观图。
- 不使用来源不明的网络图片。
- 不展示精确坐标、安防设备、库房布局和未公开遗址信息。
- AI 生成图片必须标注为演示素材，不能伪装成真实病害证据。
- 页面出现地图时必须使用有审图号的合法地图；MVP 建议完全不使用地图。

## 9. 响应式与无障碍

- 桌面基准：`1440 × 1024`。
- 笔记本基准：`1280 × 800`。
- 平板：`768 × 1024`。
- 手机：`375 × 812`。
- 桌面端完成复杂录入、风险复核和证据审核。
- 手机端完成查看、轻量确认和任务提醒，复杂巡查使用单栏布局。
- 正文对比度至少 4.5:1，键盘焦点清晰可见。
- 所有输入框有始终可见的标签，不能只依赖 placeholder。

## 10. 交付与验收

设计方需要交付：

- Figma 可编辑源文件。
- 颜色、字体、间距和圆角设计变量。
- 10 个主要页面的桌面端设计。
- 登录、工作台、巡查详情、任务详情和移动端适配。
- 组件及主要状态、可点击原型和导出图标。
- 一条从创建巡查到任务关闭的完整可点击流程。

验收时必须满足：

- 四个角色均能看清自己的主要任务。
- 风险未确认、证据不足和模型降级状态表达正确。
- 规范来源、风险、任务、证据和复核记录能够相互关联。
- 375 px 页面无横向滚动，文字不溢出按钮和卡片。
- 不用真实敏感地点或来源不明图片。
- 设计可以直接转成 Next.js、Tailwind CSS 和 shadcn/ui 组件。

## 11. 可直接发给 AI 工具的提示词

```text
请设计一套“文巡智护”桌面端 Web 专业工作台，用于文物建筑巡查、风险复核、整改任务和报告归档。它不是营销网站、数字人讲解或聊天机器人。

用户包括巡查人员、整改责任人、复核人员和管理员。核心流程是：巡查人员创建巡查并填写现场记录；智能体生成检查计划、风险草案和规范依据；复核人员确认风险并创建整改任务；整改责任人提交证据；复核人员通过或驳回；全部风险关闭后生成报告。

请设计登录页、工作台、建筑档案列表、建筑档案详情、新建巡查、巡查详情与智能体工作台、整改任务列表、整改任务详情、规范知识库和报告中心。

巡查详情是最重要的页面。左侧展示原始记录、巡查计划、风险等级、建议处置、不确定项和规范原文；右侧展示 Agent Provider、模型、Prompt 版本、工具调用数量、运行状态和降级提示。每条风险都要有明显的人工确认按钮，未确认时不能出现“整改中”。

风格要克制、专业、可信，有档案和调查记录感。使用冷调浅灰背景、白色面板、氧化铜绿主色、朱砂红高风险和土金待处理色。中文字体使用 Noto Sans SC 或系统字体，编号使用等宽字体，卡片圆角不超过 8px，图标使用 Lucide，状态同时使用文字和颜色。

必须设计空状态、加载、分析失败、模型降级、风险待确认、风险已确认、证据不足、任务驳回、期限临近、期限逾期和权限不足。不要营销 Hero、数字人、聊天窗口、紫色渐变、发光装饰或卡片套卡片。

请交付 Figma 可编辑源文件、设计变量、组件状态、1440px 与 375px 画板，以及覆盖完整业务闭环的可点击原型。
```
