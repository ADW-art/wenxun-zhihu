最后更新：2026-09-25

## 2. 产品目标与非目标

### 2.1 产品目标

文巡智护是文物建筑智能巡查与保护整改智能体，主要交互形态为 Web 工作台。智能体把建筑档案、巡查计划、现场记录、AI 风险草案、规范引用、人工复核、整改任务、整改证据和归档报告连接为可追踪闭环。

AI 只承担识别、检索、风险提示、证据完整性检查和文档草案；风险确认、整改要求、复核和归档必须由具备权限的人员完成。

### 2.2 非目标

- 自动结构安全鉴定或替代文保专家结论。
- 自动批准修复方案、执法结论或最终责任认定。
- IoT、无人机、三维扫描、数字孪生和多智能体编排。
- 在公开演示中展示精确坐标、安防设施、库房布局或未公开遗址信息。
- 营销型首页、数字人、通用聊天首页和无业务依据的大屏。

## 3. 用户角色与职责

| 角色                 | UI 中的主要任务                                          | 不可执行                                     |
| -------------------- | -------------------------------------------------------- | -------------------------------------------- |
| 巡查人员 INSPECTOR   | 创建巡查、填写现场记录、上传照片、运行智能分析、提交风险 | 确认风险、创建整改任务、关闭任务、管理规范库 |
| 整改责任人 RECTIFIER | 查看分配任务、读取验收标准、提交整改说明和证据           | 确认风险、审批整改、关闭巡查                 |
| 复核人员 REVIEWER    | 确认或排除风险、创建整改任务、复核证据、通过或驳回       | 提交其他责任人的整改证据                     |
| 管理员 ADMIN         | 管理建筑、用户、规范知识库和系统配置                     | 绕过审计或人工确认直接关闭风险               |

界面不可只通过隐藏按钮表达权限。无权限时，应提供明确原因和可执行的返回路径。

## 4. 核心任务与闭环

```text
选择建筑点位
  -> 创建巡查并填写季节、天气和现场观察
  -> 上传现场照片与附件
  -> AI 生成检查计划、风险草案和规范候选
  -> 巡查人员修订并提交
  -> 复核人员确认、排除或要求补充
  -> 从已确认风险创建整改任务
  -> 整改责任人提交说明和证据
  -> AI 检查证据完整性
  -> 复核人员通过或驳回
  -> 全部风险关闭后导出报告并归档
```

### 4.1 业务结构表

| 步骤     | 操作者                 | 输入                               | 系统/AI 行为                       | 人工确认点                 | 异常与完成状态             | 审计                         |
| -------- | ---------------------- | ---------------------------------- | ---------------------------------- | -------------------------- | -------------------------- | ---------------------------- |
| 创建巡查 | 巡查人员               | 建筑、季节、天气、现场观察         | 校验字段并建立草稿                 | 无                         | 必填错误、保存失败         | 创建者、时间、建筑           |
| 采集证据 | 巡查人员               | 照片、附件、说明                   | 校验类型、大小、授权和脱敏元数据   | 人工确认照片与文字说明对应 | 格式错误、过大、上传失败   | 原文件名、存储键、来源类型   |
| AI 初判  | 巡查人员或复核人员触发 | 巡查文本、建筑档案、候选规范       | 生成计划、风险草案、引用和不确定项 | 不得自动确认风险           | 超时、Schema 失败、降级    | Agent 版本、模型、工具、耗时 |
| 风险复核 | 复核人员               | AI 草案、原始记录、规范原文        | 展示证据链和风险历史               | 必须人工确认或排除         | 待确认、已确认、已排除     | 复核人、意见、时间           |
| 创建任务 | 复核人员               | 已确认风险、责任人、期限、验收标准 | 写入任务并建立关系                 | 必须指定责任人和期限       | 待处理、分配失败           | 创建者、责任人和截止时间     |
| 提交整改 | 整改责任人             | 说明、照片、附件                   | 检查证据完整性但不自动关闭         | 提交人确认内容             | 处理中、待复核、证据不足   | 提交人、文件、来源           |
| 整改复核 | 复核人员               | 任务、证据、AI 初审                | 显示缺项、驳回原因和历史           | 必须人工通过或驳回         | 已关闭、已驳回             | 复核人、意见、审批链         |
| 报告归档 | 复核人员或管理员       | 已关闭巡查                         | 汇总风险、依据、任务和证据         | 归档前检查未关闭项         | 可导出、不可导出、缺失来源 | 报告版本、导出人、时间       |

## 5. 页面范围与优先级

### 5.1 比赛核心页面

1. 登录与角色入口。
2. 巡查工作台与建筑点位。
3. 巡查详情、证据工作台和 AI 初判。
4. 风险复核与整改任务。
5. 复查归档与报告中心。

### 5.2 完整页面清单

| 页面                   | 唯一主任务                          |
| ---------------------- | ----------------------------------- |
| 登录页                 | 识别用户及角色后进入工作区          |
| 工作台                 | 判断待办、风险和近期闭环进度        |
| 建筑档案列表           | 找到可巡查建筑并进入档案            |
| 建筑档案详情           | 查看建筑历史风险并创建巡查          |
| 新建巡查               | 完成现场记录和证据采集              |
| 巡查详情与智能体工作台 | 对照证据、AI 初判和规范完成人工复核 |
| 整改任务列表           | 找到并打开需要处理或复核的任务      |
| 整改任务详情           | 提交、审核或驳回整改证据            |
| 规范知识库             | 查看规范条款、来源和适用范围        |
| 报告中心               | 查看报告数据并导出归档报告          |

## 6. 设备与响应式

| 设备   | 基准        | 主要能力                                     |
| ------ | ----------- | -------------------------------------------- |
| 桌面   | 1440 × 1024 | 全部巡查、复核、任务和报告流程               |
| 笔记本 | 1280 × 800  | 全部业务能力，保持可读信息密度               |
| 平板   | 768 × 1024  | 单栏查看、轻量填写和复核                     |
| 手机   | 375 × 812   | 查看、提醒、轻量确认和提交；复杂巡查优先桌面 |

375 px 是项目已确认基准，不采用模板中的 390 × 844。设计可以同时验证 390 px，但验收以 375 px 为准。

## 7. 成功标准

- 四类角色能看清自己的主要任务和不可执行操作。
- 从创建巡查到整改关闭的报告闭环可以完成。
- 风险未人工确认前，不出现“整改中”。
- 每条风险可追溯到规范来源，或明确标记信息不足。
- 证据不足、模型降级、权限不足和接口失败均有可继续的界面。
- Token 和组件可以直接映射到 Next.js、Tailwind CSS 与现有 React 组件。
- 关键页面在 1440 px 和 375 px 下无横向滚动、文字溢出或内容遮挡。

## 8. 业务、数据与安全限制

- 不展示精确坐标、安防设备、库房结构和未公开遗址信息。
- 现场照片需支持人脸、车牌、证件和住址等个人信息脱敏。
- 演示图片必须记录来源和授权；AI 生成图片必须标记为演示素材。
- 已关闭任务不可重复提交，只能查看历史或由有权限人员新建修正记录。
- 模型失败时保留原始输入，并允许使用明确标识的预置结果继续演示。
- 正式风险结论、整改要求和归档必须保留操作者、时间和审批链。

## 9. 已确认、假设与待确认

### 已确认

- 项目名称：文巡智护。
- 项目定位：文物建筑智能巡查与保护整改智能体。
- 四类角色：巡查人员、整改责任人、复核人员、管理员。
- 核心闭环：巡查、AI 初判、人工确认、整改、复核、归档。
- 桌面与移动基准见第 6 节。
- 视觉方向和基础色见 `docs/UI_SPEC.md` 与 `docs/ui/UI_DESIGN_SYSTEM.md`。

### 工程假设

- 首版继续使用 Next.js、Tailwind CSS v4、Lucide 和现有 React 组件。
- Figma 继续通过 Figwright 本地插件桥接，不使用 Figma REST Token 作为当前主路径。
- 当前不引入暗色模式、第二品牌或 Storybook。

### 待确认

- 目标 Figma 是新建专用文件还是在现有文件中新建页面。
- 目标用户或近似用户走查尚未执行。
- 来源明确且可公开展示的文物建筑图片尚未确定。
