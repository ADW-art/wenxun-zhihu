# 需求规格

最后更新：2026-09-24

## 1. 功能需求

| ID     | 需求               | 验收条件                                     |
| ------ | ------------------ | -------------------------------------------- |
| FR-001 | 用户登录与角色识别 | 四类测试账号登录后进入对应权限范围           |
| FR-002 | 文物建筑档案       | 管理员可以查看和编辑脱敏建筑档案             |
| FR-003 | 创建巡查           | 巡查人员可以创建巡查并提交文字、数值和图片   |
| FR-004 | 智能巡查计划       | 智能体根据建筑类型、季节和历史风险生成检查项 |
| FR-005 | 风险分析           | 智能体输出结构化风险、等级、理由和不确定项   |
| FR-006 | 规范引用           | 每条已确认风险至少关联一个知识库条款和来源   |
| FR-007 | 人工确认           | 未经复核人员确认，风险不能直接进入关闭状态   |
| FR-008 | 整改任务           | 可以从已确认风险创建责任人、期限和验收标准   |
| FR-009 | 整改证据           | 责任人可以提交说明、图片和整改结果           |
| FR-010 | 智能复核           | 智能体检查证据完整性，但不得自动关闭任务     |
| FR-011 | 人工复核           | 复核人员可以关闭或驳回整改任务               |
| FR-012 | 档案报告           | 系统可以生成完整过程报告和来源清单           |
| FR-013 | Agent 运行记录     | 记录 Provider、模型、工具、耗时、结果和错误  |
| FR-014 | 降级模式           | Provider 失败时使用 Mock Provider 维持演示   |

## 2. 非功能需求

| ID      | 需求     | 验收条件                                     |
| ------- | -------- | -------------------------------------------- |
| NFR-001 | 安全     | 密钥不入库、不入日志、不进入客户端           |
| NFR-002 | 权限     | 服务端校验角色和资源归属                     |
| NFR-003 | 输入校验 | API 和 Agent 输出均通过 Zod Schema           |
| NFR-004 | 可追踪   | 每个判断关联巡查、Agent Run 和知识库来源     |
| NFR-005 | 可测试   | 单元、集成、Agent 和浏览器冒烟验证可重复运行 |
| NFR-006 | 可部署   | 支持 Docker Compose 和公网部署               |
| NFR-007 | 可访问   | 键盘操作、焦点可见、对比度至少 4.5:1         |
| NFR-008 | 性能     | 常规页面 P95 在本地环境小于 2 秒             |

## 3. 用户故事

- 作为巡查人员，我希望系统先给我检查清单，避免遗漏季节性和历史风险。
- 作为巡查人员，我希望风险结论附规范依据，而不是只有模型建议。
- 作为整改责任人，我希望明确看到期限、证据要求和驳回原因。
- 作为复核人员，我希望看到证据链和 Agent 运行记录后再决定关闭。
- 作为管理员，我希望替换模型供应商时不修改核心业务代码。

## 4. MVP 通过条件

- 三条核心巡查案例可以完成闭环。
- 至少一条案例包含证据不足和驳回后重新提交。
- 至少一条案例包含 Provider 超时并使用降级结果。
- 所有测试和生产构建通过。
