## Context

项目已有 Next.js 16、Tailwind CSS v4、Prisma 状态机、真实巡查服务和完整测试。Figma 已确认 6 个桌面主流程页面和 2 个移动采集页面，但尚未组件化，代码 Token 仍是旧版氧化铜绿。开发需要在不改变 API、权限和业务状态机的前提下，把视觉重构为可复用组件。

## Goals / Non-Goals

**Goals:**

- 同步新视觉 Token 和深色 App Shell。
- 实装风险地图、巡查总览、巡查详情、任务详情和报告中心。
- 复用现有 Prisma 查询和服务端操作。
- 补齐核心页面基础状态与 375 px 响应式。
- 保持代码可测试、可回滚、无敏感数据。

**Non-Goals:**

- 不实现统计分析和系统管理。
- 不接入真实地图 SDK。
- 不新增审批状态或改写现有权限。
- 不把参考图照片作为正式证据。
- 不复制第三方设计资产中来源不明的图片。

## Decisions

### 决策一：保留当前路由和 Prisma 状态机

使用现有 `/dashboard`、`/inspections/[id]`、`/tasks/[id]`、`/reports`，新增 `/risk-map`。相比重新搭建路由，可以保留 API、权限和测试。

### 决策二：共享组件先服务于页面，不建立空泛通用层

优先创建 `PageHeader`、`MetricCard`、`EvidenceGallery`、`StatusTimeline` 和 `TaskTable` 等项目组件；不为一次性布局创建抽象。

### 决策三：地图使用示意资产

使用 `design/assets/heritage-risk-map-v1.png` 作为背景，配合脱敏点位。该页不声称地图授权，不展示精确坐标。

### 决策四：桌面优先、移动保持可用

以 1440 px 的 Figma 设计为基线，在 375 px 下折叠侧栏为顶部导航、将多栏内容变单栏，不追求完整移动工作流。

### 决策五：状态通过小型共享组件表达

Loading、Empty、Error、Permission 和 Read-only 统一使用组件；AI 降级、证据不足和任务驳回保持业务语义。

## Risks / Trade-offs

- [参考图照片授权不明] → 代码不引用参考截图，使用项目资产或明确占位。
- [地图资产可能被误认为正式地图] → 页面显示“示意地图，不提供定位信息”，仅使用脱敏地区标签。
- [Figma 组件缺失导致代码不一致] → 在代码中抽取共享组件，后续用截图对比校正。
- [一次性重构页面范围较大] → 按页面逐步替换，每阶段运行完整检查并提交 GitHub。
- [375 px 专业表格过密] → 移动端转为行卡片或隐藏次要列。

## Migration Plan

1. 同步 Token、App Shell 和基础反馈组件。
2. 实装风险地图和巡查总览。
3. 重构巡查详情和复核流程。
4. 重构整改任务详情。
5. 重构报告中心与状态页。
6. 运行完整检查、Playwright 截图和 GitHub 推送。
7. 如出现问题，回滚到最近的页面级提交，不回滚用户设计资产。
